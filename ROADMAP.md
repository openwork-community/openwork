# OpenWork Roadmap

**Planning document — not a promise of release dates or completed functionality.**

## Phase 0 — Founding community

- [x] Create public GitHub organization and initial repository.
- [x] Select Apache License 2.0.
- [ ] Publish project mission, contribution, conduct, and governance documents.
- [ ] Enable GitHub Discussions with introductions, ideas, and technical design categories.
- [ ] Establish a private contact for conduct and security reports.
- [ ] Gather contributors across development, QA, accessibility, design, and documentation.
- [ ] Validate the MVP workflow with prospective creators and contributors.
- [ ] Agree on technical design through a public discussion.

## Phase 1 — Self-hostable MVP

**Goal:** Help someone propose a useful project, discover a team, and begin collaborating.

- [ ] Public project directory and project detail pages.
- [ ] Submit and review project proposals.
- [ ] Describe contributor roles and express interest in joining.
- [ ] Basic project lifecycle states (proposed, recruiting, building, released, archived).
- [ ] Links to source repositories and published projects.
- [ ] Essential moderation, privacy, and access controls.
- [ ] Accessible, responsive interface.
- [ ] Documented local setup, self-hosted deployment, and tests.

## Phase 2 — Better collaboration

- [ ] Maintainer and team workflows.
- [ ] Optional GitHub integration for repository information and verifiable contributions.
- [ ] Contributor onboarding, milestones, and notifications where useful.
- [ ] Public release and maintenance status.

## Phase 3 — Sustainable ecosystem

- [ ] Multiple independent community projects with trusted maintainers.
- [ ] Stronger governance and moderation.
- [ ] Additional source-hosting integrations where practical.
- [ ] Accessibility, localization, backups, upgrades, and operational documentation.

## Constraints

Open source, no mandatory subscriptions or paid service dependencies, self-hostable, privacy-first, accessible, and grounded in real community needs. We should reuse Git and existing code-review tools rather than recreating them.

## Suggest a change

Open a clear [GitHub Issue](https://github.com/openwork-community/openwork/issues) with the problem, intended users, rationale, and expected implementation trade-offs.

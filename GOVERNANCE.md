# OpenWork Governance (Founding Stage)

OpenWork aims to become genuinely community-governed. The model below describes the **initial founding stage**, not an existing elected leadership body.

## Current stewardship

The founding repository maintainer currently handles repository administration, permissions, moderation, and initial project decisions. These responsibilities should gradually be shared with trusted contributors as the project matures.

## Making decisions

1. Publish significant proposals in an issue or public discussion.
2. Explain user benefits, risks, costs, accessibility, security, and self-hosting impact.
3. Invite feedback and seek reasoned consensus.
4. Record the outcome and rationale publicly, except for sensitive security or personal matters.
5. Reconsider decisions when new evidence emerges.

While OpenWork is forming, the founding maintainer makes final repository decisions. This is a temporary operating arrangement rather than a promise of permanent unilateral authority.

## Roles

- **Contributors:** Anyone improving documentation, design, tests, code, ideas, or community work.
- **Project maintainers:** Trusted contributors who review work, guide new contributors, and steward particular repositories.
- **Organization administrators:** A limited number of trusted people handling sensitive settings, security, and access.

Maintainer access should reflect constructive contributions, reliability, and community trust. We'll establish transparent nominations and review criteria before adding maintainers.

## Choosing projects

Proposals should describe real users and needs, a manageable initial scope, licensing, maintenance responsibilities, and relevant risks. Popularity alone shouldn't decide what gets built.

## Transparency and privacy

Decisions and source code should be public whenever appropriate. This does not require exposing personal information, private reports, security credentials, or moderation details.

## Disputes and amendments

Technical disagreements should focus on evidence and trade-offs. Conduct problems are handled under our [Code of Conduct](CODE_OF_CONDUCT.md). Changes to governance should be proposed publicly and documented.
